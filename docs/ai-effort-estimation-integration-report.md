## Summary

The "Estimate Calibrated Effort" feature has been completely repaired. Prior to this work, clicking the estimation button **never called any external AI model** — 100% of estimates were silently generated by `MockAIProvider` (a deterministic heuristic). This report documents the investigation findings, all changes made, and verification results.

---

## Investigation Findings

### Root Causes Identified

| # | Finding | Impact |
|---|---------|--------|
| 1 | `GeminiProvider.estimate_effort()` returned `await self.fallback.estimate_effort(request)` — 100% delegated to `MockAIProvider` | **No real AI was ever called** |
| 2 | All other `GeminiProvider` methods also silently fell back to `MockAIProvider` | No AI features used real models |
| 3 | `EffortEstimationRequest.title` had no validator; missing title caused HTTP 500 not HTTP 422 | Silent server errors, no client feedback |
| 4 | `AddWorkView.tsx` `handleEstimateEffort` had empty `catch {}` — all errors swallowed silently | Users saw no error on failure |
| 5 | No `.env` file existed; `GEMINI_API_KEY` was `None`; `AI_PROVIDER` defaulted to `"mock"` | Key was not loaded even if present |
| 6 | `config.py` did not recognize `GOOGLE_API_KEY` as valid alias | Key resolution incomplete |

## Changes Made

### Backend

#### `config.py`
- Added `GOOGLE_API_KEY` as recognized alias for `GEMINI_API_KEY`
- Added `GEMINI_MODEL: str = "gemini-1.5-flash"` (configurable)
- Added `AI_TIMEOUT_SECONDS: float = 15.0`
- Added `effective_gemini_api_key` property (resolves either key)
- Added `is_gemini_configured` property

#### `errors.py`
Five new typed AI exception classes:

| Exception | HTTP Status | Code |
|-----------|------------|------|
| `AIConfigurationException` | 500 | `AI_CONFIG_ERROR` |
| `AIServiceUnavailableException` | 503 | `AI_SERVICE_UNAVAILABLE` |
| `AIRateLimitException` | 429 | `AI_RATE_LIMIT` |
| `AITimeoutException` | 504 | `AI_TIMEOUT` |
| `AIValidationException` | 502 | `AI_MALFORMED_RESPONSE` |

#### `schemas.py`
- `EffortEstimationRequest`: Added `@model_validator(mode="after")` enforcing non-empty title → HTTP 422 on missing title
- Added `GeminiEffortExtraction` internal schema with strict Pydantic field constraints

#### `provider.py` — Complete `GeminiProvider` rewrite

- `_call_gemini()`: Real HTTP POST to Google Gemini API with structured error mapping
- `estimate_effort()`: Real model call, `GeminiEffortExtraction` validation, deterministic pace factor + uncertainty interval calculations, `estimation_source: "google_gemini_calibrated"`
- All 5 provider methods implemented with real Gemini calls (zero silent mock fallbacks)
- `get_ai_provider()` factory: auto-selects `GeminiProvider` when key present

### Frontend

#### `apiTypes.ts`
- Canonical `AIEffortEstimateRequest` interface

#### `apiHooks.ts`  
- `useAIEffortEstimate()` sends `{ title, work_title, category, description, complexity, units_count }`

#### `AddWorkView.tsx`
- `handleEstimateEffort`: resets error state, surfaces caught errors to user
- Button `id="estimate-calibrated-effort-btn"` with dynamic text: `"Estimating..." / "Estimate Calibrated Effort" / "Recalibrate Effort"`
- Confidence badge and AI Model Assumptions section display
- Confirmation persists estimate to SQLite via `createMutation`

## Complete Data Flow

```
User types work description
  → handleEstimateEffort()
    → POST /api/v1/ai/estimate-effort (JWT authenticated)
      → get_ai_provider() → GeminiProvider
        → GeminiProvider.estimate_effort()
          → _call_gemini() → POST googleapis.com/...generateContent?key=GEMINI_API_KEY
            → Google Gemini API (real model call)
          → GeminiEffortExtraction validation
          → deterministic pace factor + uncertainty calculation
        → EffortEstimationResponse (estimation_source: "google_gemini_calibrated")
      ← JSON 200 response
    ← UI updates: hours, confidence, reasoning factors
  → User clicks "Confirm & Schedule Commitment"
    → POST /api/v1/work → persisted to SQLite
```

## Configuration Guide

To activate real Google Gemini AI, create `backend/.env`:

```bash
AI_PROVIDER=gemini
GEMINI_API_KEY=your_actual_gemini_api_key_here
# Optional:
GEMINI_MODEL=gemini-1.5-flash
AI_TIMEOUT_SECONDS=15.0
```

`backend/.env` is in `.gitignore` — the API key will never be committed.

**Key resolution order:**
1. `GEMINI_API_KEY` from `backend/.env`
2. `GOOGLE_API_KEY` from `backend/.env`
3. System environment variables
4. Falls back to `MockAIProvider` only when no key present and `AI_PROVIDER` not `"gemini"`

## Security Notes

- API key is **never** included in error messages, logs, or HTTP responses
- All AI endpoints require valid JWT (`Authorization: Bearer <token>`)
- Rate limiting: 10 AI requests/minute per user
